# Tree of Life museum POC

`/museum/` is a separate Vite HTML entry. Its implementation lives in `src/experience/TreeMuseum/`; the band homepage remains at `/`. This route is a local portfolio exploration and is marked `noindex`. The separate portfolio deployment targets https://satoramoto.github.io/web/.

The composition borrows the branching canopy, central blue eddy, peach roots and discreet museum labels from the generated visual reference. The artwork is rendered live rather than displaying that image. Butterchurn 2.6.7 renders three persistent WebGL canvases, which become textures in an independent WebGL2 shader compositor. A sparse branching mask and quiet crisp contours retain the tree structure. The previous eighteen static branch curves per layer have been removed. The presets supply moving detail to one normalized, spatially mixed field; the full original presets are not shown as three separate rectangles.

The selector offers three structurally different themes, with real preset banks from Butterchurn favorites / butterchurn-presets 2.4.7:

A shared bounded stereo synthesis produces one canonical mono waveform (0.8 left + 0.2 right), which drives the visible spine and all three presets. A repeating 1024-sample signal texture draws the visible lavender-blue spine, including luminous traveling swells and fading historical waveform traces. Scroll, touch and keyboard movement excite a damped energy envelope and seed irregular pulse amplitudes, speeds, widths, phases and integer spatial harmonics. Pulses begin roughly one-third down the current viewport, travel down the periodic spine, decay exponentially and expire after seven simulation seconds. Pulse count is capped at ten; gesture energy is capped at one. Signed samples are soft-limited and explicitly saturated before byte conversion.

Each independent 60 Hz signal tick stores an immutable snapshot of the synthesis. Pulse onset has a 0.22-second exponential attack and reduced bounded amplitudes. Signed samples receive temporal attack/release smoothing (0.10/0.26 seconds); pulse envelopes use 0.18/0.50 seconds. This smoothing occurs before snapshot storage and byte quantization, so the visible line, preset input and emission still use the exact same smoothed waveform. The shader also reduces envelope brightness gain and softens injection exposure; these changes address the requested gentler appearance. Upload builds the canonical mono waveform, explicitly saturating and quantizing it to bytes once. The same latest row's byte samples are copied unchanged into all three of Butterchurn's mono/left/right input arrays at each preset render. The former per-destination 0/0.16/0.32-second delays and temporal filters have been removed. A shared GLSL `signalAt` helper samples the exact byte texture at sample-centered coordinates; `signedSample` reverses the input byte encoding, and `spineAt` defines the signed sample's visible x position. Both the display and feedback-emission passes use this same position. Thus waveform drawing, local source UV displacement and emission position use the same quantized samples supplied to the presets, rather than merely sharing an energy scalar.

A 1024-by-16 texture also retains timestamp-interpolated historical canonical waveform samples and their pulse envelopes. Eleven visible ghost traces cover 0.06–0.66 seconds of past input, fade with age and travel along the curved spine. Missing startup ages are masked out. They use stored source windows, not current oscillators re-evaluated at another phase. The signal/history remains up to 60 Hz; each preset consumes the newest window at its lower, staggered quality-tier cadence. Intermediate signal snapshots need not be consumed by every preset. `waveformFeedTime` records the actual source timestamp delivered to each instance.

Butterchurn's native audio processing still applies its own FFT, smoothing and preset-specific basic/custom-wave equations. This correction does **not** replace every preset's internal waveform geometry with a literal vertical tree line. It supplies the exact shared waveform as input and spatially remaps/masks the real preset RGB output into emissions around that same line in the compositor. Presets retain their own internal feedback, which is not shared across instances.

This is a virtual signal visualization, not captured sound. The page is silent and never creates an AudioContext or requests microphone permission. Motion proceeds independently of scroll. Scrolling eases the camera along a six-unit periodic vertical world; preset history is not rewound. Three stable label anchors follow the same coordinates, and the cycle repeats indefinitely in both directions. Detail dialogs pause the visual world, trap focus through the native dialog element and restore focus to the invoking label. Escape, the close button and the backdrop return to the world.

Wheel and touch drag support spatial navigation. Arrow keys move in small steps, Page keys and Space move by a layer, and Home resets the camera. Top-right controls pause/resume animation and reset the camera. Reduced motion starts paused; the user can deliberately resume. Paused or hidden-page movement cannot add excitation. Pausing holds existing pulses, audio history, waveform traces and shared feedback stable. Gestures while paused add no excitation. Reset clears pulses, smoothing state, waveform history, trace rows and both feedback targets; the next frame seeds a fresh baseline. Pulse motion, synthesis phase and history timestamps use the same visible, unpaused simulation clock as rendering. Background tabs stop render work. Resize updates the compositor drawing buffer according to the active quality tier, capped at DPR 1 and width 1440 in high quality. Preset textures range from 192 to 512 square. Persistent instances are never recreated during scroll.

All three live preset textures contribute to a common displacement field and normalized broad spatial weights. Raw RGB is retained; each source receives a nonlinear black-point/contrast curve before mixing. A source with strong local chroma/detail dominates the mix, with quieter neighbors bleeding in, rather than averaging bright gray backgrounds into fog. Prism retains the mandala as its dominant source. All theme mappings now use local signed-waveform positions distributed along the whole world, rather than a fixed radial center at world y=3. A small saturation lift and bounded gain preserve saturated lines and dark voids. Branching coverage and quiet contours anchor the composition without confining all imagery to the former narrow tree silhouette. Mirrored source sampling and six-periodic coordinates preserve the vertical loop. The Prism source coordinate advances two mirrored UV periods per six-unit world, so the seam samples identically.

A single shared ping-pong layer advects the mixed output in world space. High-quality targets are 640 by 960; balanced targets are 384 by 640 and low targets 256 by 384, in the existing compositor context. Read and write framebuffer textures remain distinct. New preset output is injected only around the exact smoothed, sample-displaced spine at each y. A quiet narrow baseline surrounds the waveform; a traveling pulse expands that emitting width and increases exposure locally. Quiet distant areas receive no independent fullscreen preset injection: they show decaying transported history. The live preset sampling receives a quarter-turn in the spine-local frame so elongated source crests follow the line. Outward history backtraces along its local normal, with only a small tangential drift. The tangent uses a bounded, broad 0.48-world-unit secant of the same sample-displaced line, preventing fine carrier wiggles from spraying the wake into chaotic jets. Themes retain different UV mappings, outward speeds and wake decay. Presentation applies continuous exponential world-space attenuation, `0.10 + 0.90 × exp(-0.7 × distance)`, from the broadly smoothed spine. The center remains concentrated while the nonzero tail allows transported color at visible edges. Repeating phase/crest modulation and moving bright/dark stripe gates have been removed completely. A short three-tap integration along world y joins source scanlines into a gentle continuous smear. The rotated preset sampling and spine-local normal flow remain.


Emission exposure (6.5 per simulation second) is separate from wake decay (0.55–0.75 per second), so rapidly advected pulse-local RGB detail stays visible. Retained output plus new injection uses a bounded screen blend: both source and retained RGB are in [0,1], and injection consumes only the remaining channel headroom. This cannot amplify past one or accumulate unbounded brightness. Rates scale with unpaused simulation dt. The spine and UI are drawn afterward and never enter the accumulation. Camera scrolling is applied only when presenting the world texture, so scroll does not drag screen-space smears into feedback. Pause holds history and accumulation; reset clears both targets. Resize clears them because the world's horizontal extent changes with aspect; disposal deletes both textures and framebuffers.

Diagnostics are available without UI clutter at `window.__treeMuseum`: renderer name, selected presets, render-frame and MilkDrop-frame counts, world position, paused state, gesture/pulse counts, shared signal RMS, individual preset-feed RMS values, canonical waveform-feed description/timestamps, retained history count, shared-feedback frame count and target size, and an error when available. WebGL2 is required. The project labels and detail links remain available if graphics initialization fails. Context loss displays an unavailable message; recovery requires a reload.

This is an intentionally small first slice, not an exact reconstruction of the generated reference. Actual device performance and visual quality vary with WebGL support. The composer uses three independent contexts to avoid unproven cross-instance GL state sharing. The compositor adds a fourth context. Real input audio, project-specific visual assets and a native Metal engine are outside this POC.

Run using the unified launcher only, with allocated preview and Storybook ports. No automated tests were added or run, as explicitly requested for this fast POC. Type/build validation and a quick Chromium visual smoke check were used; integrated interaction acceptance belongs to the coordinator.

## Performance pass

All four WebGL2 contexts request `high-performance`; this is a preference, not evidence of hardware acceleration. Butterchurn uses a 24-by-18 warp mesh (475 equation vertices per source instead of the default 48-by-36 mesh's 1,813). Preset updates aim at 30 Hz each and are staggered, with at most two destinations rendered per display frame. The shared stereo synthesis and historical input texture update independently at up to 60 Hz, including on high-refresh displays. Snapshot arrays are recycled only after leaving retained history. `milkFrames` now counts individual destination renders.

The twelve expensive procedural branches are cached in a 512-by-768 world-space GPU mask, refreshed at 15 Hz because their motion is slow. The feedback and presentation shaders sample this mask instead of evaluating branch curves for every screen pixel. The eleven historical-waveform loops execute only inside the bounded spine band. Texture storage is allocated once and recurring updates use `texSubImage2D`; this avoids redefinition but does not eliminate cross-context canvas transfer. Uniform locations are cached. Idle label positions are no longer rewritten every RAF.

The tiered display/preset/feedback resolution caps reduce GPU work. Tradeoffs are a coarser preset warp mesh, slightly softer upscaled field detail and 15 Hz contour motion. Waveform input is not throttled to the preset cadence. This pass targets smooth 60 fps presentation; it does not establish that every device achieves it.

Append `?perf=1` to `/museum/` for the opt-in DOM-visible HUD. It reports rolling RAF frequency and RAF-interval p95, renderer CPU-submission mean/p95, canvas and feedback dimensions, requested context preference and the exposed renderer string. CPU submission includes synthesis, destination rendering calls, uploads and compositor submission; it is not a GPU completion time. GPU timer queries, when supported, are asynchronous and discard disjoint results. Their timing covers only the compositor context, including its mask/feedback/presentation passes; all three Butterchurn contexts are excluded. No `gl.finish` or `readPixels` is used. An unavailable GPU timer remains explicitly unavailable. Use the running, unpaused page after warmup for a meaningful measurement; a paused page's RAF rate is not an active-rendering performance claim.

## Adaptive quality

Quality defaults to `auto`, initially high. A small controller measures actual, unclamped RAF wall intervals only while visible, focused and unpaused. Initial startup, resume, resize, theme changes and tier reallocations start a four-second observation warmup. It evaluates approximately one-second windows (at least two samples), requiring three sustained slow windows below 54 fps or above 24 ms p95 before lowering one tier. Recovery requires fifteen consecutive windows at least 58.5 fps and below 19 ms p95. A downgrade adds a ten-second cooldown; upgrades add twenty-five seconds. Genuine long active-rendering intervals remain evidence of overload, rather than repeatedly restarting warmup. This conservative policy avoids reacting to paused/background time and reduces tier oscillation; it does not guarantee 60 fps on every device.

| Tier | Preset size / each cadence | Mixed field | Branch mask | Display cap / scale |
| --- | --- | --- | --- | --- |
| high | 512² / 30 Hz | 640 × 960 | 512 × 768 | 1440 px / 1 |
| balanced | 320² / 24 Hz | 384 × 640 | 384 × 640 | 1152 px / .85 |
| low | 192² / 18 Hz | 256 × 384 | 256 × 512 | 900 px / .65 |

Explicit `?quality=high|balanced|low` overrides automatic transitions for visual inspection. Invalid values fall back to auto. The HUD adds the active tier, reason and transition count; `window.__treeMuseum.quality` exposes the same state, including observation fps/p95. Quality changes synchronize canvas intrinsic sizes, Butterchurn renderer dimensions and compositor source texture storage, then reallocate/check/clear both feedback targets and the branch mask. Source uploads reseed all three destinations, including when paused. No extra contexts are created. The shared signal, pulse clock and waveform-history budget remain independent at up to 60 Hz in every tier; lower tiers trade source refresh/detail and display sharpness for lower work.

`npm run build:museum` performs TypeScript and destination-specific production validation. No automated tests were added or run per the user's instruction. Runtime visual/performance acceptance is owned by the coordinator, with no weaker-device or automatic-transition result claimed solely from the build.

## Portfolio deployment

`npm run build:museum` builds only the museum into `dist-museum/`, promotes its HTML to the artifact root, bundles its font with `/web/` asset URLs, and retains `credits.txt`. No band homepage or band asset collection is included. The destination-specific `museum-pages.yml` workflow publishes this artifact from `codex/tree-museum-coordinator` to GitHub Pages in `satoramoto/web`. The source repository and Pages website are public. The original band deployment is restricted to its original repository. This fast POC workflow runs the production/type build without automated tests, as requested.
