# Tree of Life museum POC

`/museum/` is a separate Vite HTML entry. Its implementation lives in `src/experience/TreeMuseum/`; the band homepage remains at `/`. This route is a local portfolio exploration and is marked `noindex`. It has not been published as part of this assignment.

The composition borrows the branching canopy, central blue eddy, peach roots and discreet museum labels from the generated visual reference. The artwork is rendered live rather than displaying that image. Butterchurn 2.6.7 renders three persistent WebGL canvases, which become textures in an independent WebGL2 shader compositor. A sparse branching mask and quiet crisp contours retain the tree structure. The previous eighteen static branch curves per layer have been removed. The presets supply moving detail to one normalized, spatially mixed field; the full original presets are not shown as three separate rectangles.

Presets (from Butterchurn favorites, provided by butterchurn-presets 2.4.7):

- **Flexi + Martin — astral projection**, source ID `80b9a123a5713128ca06c61c` (`presets/astral.json`)
- **Geiss — Spiral Artifact**, source ID `824c876b9cbaf604932cc9fa` (`presets/spiral.json`)
- **Flexi + Martin — cascading decay swing**, source ID `a78e4a1c46e08aaf9efe8635` (`presets/cascade.json`)

These JSON presets were copied from the BlackHole visualizer's local builtin preset catalogue. Author credits above are retained from that catalogue. MIT notices for Butterchurn and the preset package are kept beside the implementation and preset files. The build also includes `/museum/credits.txt` with the credits and MIT notice, referenced by the museum HTML license link. No historical OpenFlow implementation was vendored.

A shared bounded stereo synthesis drives the central waveform and all three presets. A repeating 1024-sample signal texture draws the visible lavender-blue spine, including luminous traveling swells and fading historical waveform traces. Scroll, touch and keyboard movement excite a damped energy envelope and seed irregular pulse amplitudes, speeds, widths, phases and integer spatial harmonics. Pulses begin roughly one-third down the current viewport, travel down the periodic spine, decay exponentially and expire after seven simulation seconds. Pulse count is capped at ten; gesture energy is capped at one. Signed samples are soft-limited and explicitly saturated before byte conversion.

Each MilkDrop tick stores an immutable snapshot of the shared synthesis. The three preset feeds read delays of 0, 0.16 and 0.32 seconds from a bounded 128-snapshot history, then apply separate temporal filters. Destination filtering never mutates the shared snapshot. The waveform displays the latest stored source snapshot; the preset feeds are delayed, filtered versions of that shared signal. A 1024-by-16 texture stores timestamp-interpolated historical signed samples and their pulse envelopes. Eleven visible ghost traces cover 0.06–0.66 seconds of past input, fade with age and move gently down the curved spine. Missing startup ages are masked out. These traces use stored input windows that actually fed the preset-delay/filter pipeline; they are not current oscillators re-evaluated at another phase. The display shows pre-filter source samples, not a claim to visualize each destination's filtered waveform exactly. This is a virtual signal visualization, not captured sound. The page is silent and never creates an AudioContext or requests microphone permission. Motion proceeds independently of scroll. Scrolling eases the camera along a six-unit periodic vertical world; preset history is not rewound. Three stable label anchors follow the same coordinates, and the cycle repeats indefinitely in both directions. Detail dialogs pause the visual world, trap focus through the native dialog element and restore focus to the invoking label. Escape, the close button and the backdrop return to the world.

Wheel and touch drag support spatial navigation. Arrow keys move in small steps, Page keys and Space move by a layer, and Home resets the camera. Top-right controls pause/resume animation and reset the camera. Reduced motion starts paused; the user can deliberately resume. Paused or hidden-page movement cannot add excitation. Pausing holds existing pulses, audio history, waveform traces and shared feedback stable. Gestures while paused add no excitation. Reset clears pulses, delayed history, filter state, trace rows and both feedback targets; the next frame seeds a fresh baseline. Pulse motion, synthesis phase and history timestamps use the same visible, unpaused simulation clock as rendering. Background tabs stop render work. Resize updates the compositor drawing buffer, capped at DPR 1 and width 1440. Preset textures use 320-square buffers on desktop and 256-square on initial mobile layout. Persistent instances are never recreated during scroll.

All three live preset textures contribute to one common displacement field and normalized broad spatial weights. Their moving luminance is contrast-shaped into the blue, violet and peach tree palette, preventing a bright red source from turning the whole mix muddy. The shared field fills a soft branching silhouette, while twelve quiet contours keep the tree recognizable. Mirrored source sampling and six-periodic world coordinates soften source edges and preserve the vertical loop.

A single shared ping-pong layer advects the mixed output in world space. Desktop targets are 384 by 640; initial mobile targets are 256 by 512, in the existing compositor context. Read and write framebuffer textures remain distinct. Decay and injection use a bounded, time-scaled convex mix; feedback cannot amplify itself indefinitely. The spine and UI are drawn afterward and never enter that accumulation. Camera scrolling is applied only when presenting the world texture, so scroll does not drag screen-space smears into feedback. Reset clears both targets. Resize clears them because the world's horizontal extent changes with aspect; disposal deletes both textures and framebuffers. Each MilkDrop preset also retains its own internal feedback.

Diagnostics are available without UI clutter at `window.__treeMuseum`: renderer name, selected presets, render-frame and MilkDrop-frame counts, world position, paused state, gesture/pulse counts, shared signal RMS, individual preset-feed RMS values, retained history count, shared-feedback frame count and target size, and an error when available. WebGL2 is required. The project labels and detail links remain available if graphics initialization fails. Context loss displays an unavailable message; recovery requires a reload.

This is an intentionally small first slice, not an exact reconstruction of the generated reference. Actual device performance and visual quality vary with WebGL support. The composer uses three independent contexts to avoid unproven cross-instance GL state sharing. The compositor adds a fourth context. Real input audio, project-specific visual assets and a native Metal engine are outside this POC.

Run using the unified launcher only, with allocated preview and Storybook ports. No automated tests were added or run, as explicitly requested for this fast POC. Type/build validation and a quick Chromium visual smoke check were used; integrated interaction acceptance belongs to the coordinator.

## Performance pass

All four WebGL2 contexts request `high-performance`; this is a preference, not evidence of hardware acceleration. Butterchurn uses a 24-by-18 warp mesh (475 equation vertices per source instead of the default 48-by-36 mesh's 1,813). Preset updates aim at 30 Hz each and are staggered, with at most two destinations rendered per display frame. The shared stereo synthesis and historical input texture update independently at up to 60 Hz, including on high-refresh displays. Snapshot arrays are recycled only after leaving retained history. `milkFrames` now counts individual destination renders.

The twelve expensive procedural branches are cached in a 512-by-768 world-space GPU mask, refreshed at 15 Hz because their motion is slow. The feedback and presentation shaders sample this mask instead of evaluating branch curves for every screen pixel. The eleven historical-waveform loops execute only inside the bounded spine band. Texture storage is allocated once and recurring updates use `texSubImage2D`; this avoids redefinition but does not eliminate cross-context canvas transfer. Uniform locations are cached. Idle label positions are no longer rewritten every RAF.

The fixed display/preset/feedback resolution caps reduce GPU work. Tradeoffs are a coarser preset warp mesh, slightly softer upscaled field detail and 15 Hz contour motion. Waveform input is not throttled to the preset cadence. This pass targets smooth 60 fps presentation; it does not establish that every device achieves it.

Append `?perf=1` to `/museum/` for the opt-in DOM-visible HUD. It reports rolling RAF frequency and RAF-interval p95, renderer CPU-submission mean/p95, canvas and feedback dimensions, requested context preference and the exposed renderer string. CPU submission includes synthesis, destination rendering calls, uploads and compositor submission; it is not a GPU completion time. GPU timer queries, when supported, are asynchronous and discard disjoint results. Their timing covers only the compositor context, including its mask/feedback/presentation passes; all three Butterchurn contexts are excluded. No `gl.finish` or `readPixels` is used. An unavailable GPU timer remains explicitly unavailable. Use the running, unpaused page after warmup for a meaningful measurement; a paused page's RAF rate is not an active-rendering performance claim.

Build/type validation passed for the performance code. Browser timing remains unverified in this assignment because the available browser-control connection could not navigate; the HUD is provided for measurement in the user's Chrome session. No 60 fps or hardware-GPU result is claimed without that runtime evidence.
